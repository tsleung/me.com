Working…

One thing first

Deep Space reads your screenshots using Google’s Gemini. None of it works without a Gemini API key, so let’s get that in place before anything else. It takes about a minute and is free to start.

  1. Open Google AI Studio → API keys and sign in with your Google account.
  2. Press Create API key, then copy the key.
  3. Paste it below.

The key stays on this computer. It is sent to Google when you press Analyze, and nowhere else. It is never written into a backup file.

Screens

    Paste a screenshot to begin

    Take a picture of the game window with your computer’s screenshot tool, then click anywhere on this page and press Ctrl+V — or ⌘+V on a Mac. That is the quickest way in.

    You can also drag an image file onto this window, choose a file from the list on the left, or press “Capture screen” to grab the game window directly.

    How to use this
    

          
    
            You play the game as usual. When you get stuck on a screen, you take
            a picture of it, paste it in here, and press one button. The app
            describes what it sees, works out what to send back, and remembers
            what it learns so it can help more on the next screen.
          
    

          
    Setting up, once
    
          
      
            
    1. 
              You need a free Gemini API key from Google. The first screen you
              saw explains where to get one; you can also find the link in
              Settings.
            
      2. 
            
    2. 
              In Settings, press
              Make storage permanent. Without it a browser can
              throw your screenshots away when the disk gets full.
            
      3. 
          
    

          
    The loop, every level
    
          
      
            
    1. 
              Take a screenshot of the game. On a Mac,
              ⌘+Shift+4 then drag; on
              Windows, Win+Shift+S.
            
      2. 
            
    2. 
              Paste it here. Click anywhere on this page and
              press Ctrl+V (or
              ⌘+V). That is all — it becomes
              the next level automatically. You can also drag an image file in,
              or use + New level.
            
      3. 
            
    3. 
              Say anything useful in the note box — what
              you already tried, what changed when you clicked something. This
              is often what makes the difference between a vague answer and a
              good one.
            
      4. 
            
    4. 
              Press Analyze. From the second level onward this
              happens by itself as soon as you paste. Watch it think if you
              like; press Stop if you change your mind.
            
      5. 
          
    

          
    Reading the answer
    
          
      
            
    • 
              What to send back is the important part: the
              actual content of your reply. It assumes you already know how to
              send it.
            
      • 
            
    • 
              What to do first appears only when something has
              to be checked before the reply can be settled. Often it is empty,
              which is good news.
            
      • 
            
    • 
              Hypotheses are the competing explanations, each
              marked high, medium or low. Two hypotheses with different answers
              means it is genuinely unsure — treat it that way.
            
      • 
          
    

          
    Pointing at something specific
    
          
    
            Click anywhere on the picture to drop a numbered marker, then type
            what you want explained about that spot — “what is this
            dial for?”. The numbers are drawn onto the picture the app
            sends, so it can see exactly what you mean.
          
    

          
    When the answer is wrong
    
          
    
            Use the box under the answer to say what was wrong with it, then
            press Try again with this. The complaint goes back
            with the question, and it is kept — every complaint you have
            made about this screen is sent with each retry, so it cannot fix one
            and forget another.
          
    
          
    
            If you find yourself typing the same correction on every level,
            press Apply to every level. It becomes a standing
            instruction sent with every question from then on. You can edit
            those in Settings.
          
    

          
    The three buttons, and what each costs
    
          
      
            
    • 
              Analyze this screen — looks at the picture
              if needed, then works out an answer.
            
      • 
            
    • 
              Answer again, same picture — thinks again
              without looking at the picture afresh. Cheaper and faster. This is
              what you want after adding a note.
            
      • 
            
    • 
              Read the picture again — looks at the
              screenshot from scratch and re-describes it, without answering.
              Only needed if the description looks wrong, or after the app has
              been updated.
            
      • 
          
    

          
    What it remembers
    
          
    
            After each answer it proposes things to remember. Read them and
            press Add or Discard. Be
            reasonably strict: everything you keep is sent along with every
            future question, so a wrong entry kept now makes later answers
            worse.
          
    
          
    
            The whole point of the app is that this compounds. Level 30 is
            easier than level 3 not because the model got smarter, but because
            by then it is being told the thirty things you already worked out.
          
    

          
    How the knowledge base works
    
          
    
            The Knowledge tab shows everything remembered. Each
            entry is one small claim — what a glyph means, how a number is
            written, what a machine does — with a
            kind (numeral, glyph, operator, grammar, mechanic,
            concept, recipe), a subject naming the thing it is
            about, a confidence of high, medium or low, and the
            level it came from.
          
    
          
    
            Nothing is ever edited in place. The app keeps an append-only
            history of three kinds of change — add a new entry,
            revise an existing one, withdraw one — and
            the list you see is that history replayed from the beginning. That
            is why Rebuild from history and
            Undo the last change both work reliably: undo
            removes one recorded change and replays the rest, so everything that
            followed from it is rebuilt without it. It also means a revision
            keeps its ancestry — you can see that an entry replaced an
            earlier one rather than appearing from nowhere.
          
    
          
    
            Not everything proposed gets through. An entry that repeats
            something already known, word for word once punctuation and casing
            are ignored, is dropped rather than added twice — otherwise
            the list would grow every level with the model restating what it
            already told you. A change pointing at an entry that no longer
            exists is kept but marked as having done nothing, under
            Recorded changes that could not be applied, rather
            than vanishing quietly. Overlong fields are trimmed: a single entry
            rides along in every future question, so one runaway paragraph would
            cost you tokens forever.
          
    

          
    When two entries disagree
    
          
    
            Two active entries with the same kind and the same subject, saying
            different things, are a disagreement. These are
            listed at the top of the Knowledge tab and are worth settling
            promptly — left alone, both go into every future question, and
            the model has to guess which one you meant. Pick the one to keep and
            the other is withdrawn.
          
    
          
    
            This is the failure that actually bites, and it is why the subject
            of an entry names a concept rather than a value. Four
            different claims about the hydrogen line, each filed under its own
            number, never collide and so never get caught; four claims all filed
            under “hydrogen line” are flagged the moment the second
            one arrives.
          
    
          
    
            Withdrawn entries are not deleted. They move to
            Withdrawn entries at the bottom, out of the prompt
            but still in the history.
          
    

          
    What actually gets sent
    
          
    
            Everything learned is kept, but not all of it travels with every
            question. How much of the knowledge base to send in
            Settings caps the number of entries per question; when there are
            more than that, the highest-confidence ones go first, and recent
            ones win ties. The answer tells you how many rode along. Raise the
            cap if answers seem to have forgotten things; lower it if the model
            starts complaining about length.
          
    
          
    
            Withdrawn entries are never sent. Neither is the reading of any
            other level — only these entries carry across levels, which is
            what keeps a thirty-level game affordable.
          
    
          
    
            Run without the knowledge base answers the current
            screen with nothing remembered at all, using the same picture and
            the same description. It is there so you can check that any of this
            is earning its keep: if the answers are no worse without it, the
            entries you have been curating are not helping, and the honest thing
            is to know that.
          
    

          
    If something goes wrong
    
          
      
            
    • 
              “Google rejected the API key” —
              check it in Settings, and that the Generative Language API is
              switched on for it.
            
      • 
            
    • 
              “Gemini got stuck repeating itself”
              — a fault at Google’s end, not yours. Press Analyze
              again; it rarely happens twice.
            
      • 
            
    • 
              Answers seem to have forgotten things —
              check the Knowledge tab for entries that contradict each other,
              and raise the limit in Settings.
            
      • 
            
    • 
              Anything else — press
              Save a debug report under the answer and send the
              file on. It contains everything needed to work out what happened,
              and never contains your API key.
            
      • 
          
    

          
    Keeping your work
    
          
    
            Everything lives in this browser on this computer. Nothing is
            uploaded anywhere except the screenshot you are asking about, which
            goes to Google. Use Save a backup in Settings now
            and again — a browser is not a safe place to keep the only
            copy of anything.

    Rebuilding
    
          
    
            The screenshots are the only thing that cannot be regenerated.
            Everything else — the descriptions, the answers, the knowledge
            base — is derived from them, so it can all be rebuilt when the
            prompts improve.
